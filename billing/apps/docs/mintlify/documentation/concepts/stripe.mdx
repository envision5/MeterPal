MeterPal uses Stripe to create subscriptions and charge customers. You define plans, features and pricing in MeterPal, and Stripe objects (customers, products, prices, subscriptions, invoices) are created automatically as they're needed.

You never need to manually create or interact with these objects in Stripe. MeterPal handles the full lifecycle, and owns the customer state.

## MeterPal and Stripe responsibilities

MeterPal is the source of truth for a customer's state and what they can do. Stripe handles subscriptions and payments.

| Feature | Managed by | Details |
|---|---|---|
| Pricing and features | **MeterPal** | Define and update in MeterPal dashboard or API |
| Balances & credit ledgers | **MeterPal** | Tracked in real-time via `/check` and `/track` |
| Usage metering | **MeterPal** | Tracks usage internally, posts totals to Stripe at cycle end (if configured) |
| Feature gating | **MeterPal** | `/check` evaluates access from MeterPal's balances |
| Subscriptions and payments | **Stripe** | MeterPal creates Stripe subscriptions and charges customers |
| Invoices & receipts | **Stripe** | Generated and delivered by Stripe |
| Checkout pages | **Stripe** | Keep Stripe Checkout pages for payment method collection |
| Refunds & disputes | **Stripe** | Issue refunds directly in Stripe dashboard |

<Check>
MeterPal syncs from Stripe automatically. If you update or cancel a subscription directly in the Stripe dashboard, MeterPal will attempt to apply the same change to the corresponding customer state.
</Check>

## Connecting Stripe

There are three ways to connect your Stripe account to MeterPal:

| Method | When to use |
|---|---|
| **Default sandbox** | Automatic — every new Autumn org gets a Stripe Connect sandbox account with no setup needed |
| **OAuth** | Recommended for production. Connect via the deploy dialog in the MeterPal dashboard |
| **Secret key** | Paste your Stripe secret key directly. MeterPal creates a webhook endpoint automatically |

<Note>
When disconnecting and reconnecting a different Stripe account, existing Stripe IDs on your plans become invalid. MeterPal will recreate the products and prices in the new account when you `attach` it, but old customers and subscriptions will no longer be linked.
</Note>

## Currency

Currency is set at the organization level and defaults to `usd`. You can change it when connecting Stripe or from the developer settings page.

All new Stripe prices are created in your configured currency. Changing the currency does not migrate existing subscriptions — those remain in the original currency. New prices and subscriptions going forward will use the updated currency.

## How customers map

When you create a customer in MeterPal, you pass your own user ID (from your auth system, database, or any unique identifier) as the `customer_id`. This is the only ID you need — there's no separate "auth ID" concept.

```mermaid
flowchart LR
    A["Your app<br/><code>user_123</code>"] -->|customers.getOrCreate| B["MeterPal Customer<br/><code>user_123</code>"]
    B -->|on first billing call| C["Stripe Customer<br/><code>cus_abc123</code>"]
```

By default, a Stripe customer is **not** created when you create an MeterPal customer. The Stripe customer is created lazily — the first time a billing operation needs one (attaching a plan, opening the billing portal, setting up a payment method, etc.).

You can change this behavior:

- Pass `createInStripe: true` to create the Stripe customer immediately when the MeterPal customer is created
- Pass `stripeId: "cus_abc123"` to link an existing Stripe customer instead of creating a new one

See [Creating Customers](/documentation/customers/creating-customers#stripe-integration) for details.

Once linked, the mapping is bidirectional:
- **MeterPal → Stripe**: the Stripe customer ID is stored on the MeterPal customer
- **Stripe → MeterPal**: the MeterPal customer ID is stored in the Stripe customer's `metadata`

## How products and prices map

The table below shows what maps to what:

| MeterPal object | Stripe object |
|---|---|
| Plan | Product |
| Fixed price (on a plan) | Price |
| Usage-based price (on a plan) | Separate Product + Price per feature |
| Customer | Customer |
| Subscription | Subscription |

<Note>
  In production, Stripe products and prices are lazily created — only on the first `attach` that uses them, not when you create or update a plan in MeterPal. This means you can pre-map an MeterPal plan to an existing Stripe product/price before the first attach, and MeterPal will reuse it instead of creating a duplicate.
</Note>

### Fixed prices

Each fixed price on a plan maps 1:1 to a Stripe price, attached to the plan's Stripe product.

### Usage-based prices

Usage-based prices are more complex. For each priced feature, MeterPal creates a **separate Stripe product** (named `"Plan Name - Feature Name"`) with its own Stripe price. Depending on the billing model, MeterPal may also create:

- An empty placeholder price to anchor the subscription
- A billing meter for in-arrear usage reporting
- A prepaid price for upfront usage billing

These are all managed automatically — you don't need to configure them.

### Renaming in Stripe

You can rename products and update their descriptions directly in the Stripe dashboard for display purposes (e.g., on invoices or the customer portal). MeterPal won't overwrite these cosmetic changes.

<Note>
Renaming in Stripe is purely cosmetic. The plan's ID and configuration are still managed in MeterPal. For structural changes (prices, features, billing model), always use MeterPal.
</Note>

## Webhooks

MeterPal automatically creates and manages webhook endpoints when you connect Stripe. You don't need to configure these manually.

MeterPal listens for key Stripe events to keep state in sync:

| Event | What MeterPal does |
|---|---|
| `checkout.session.completed` | Finalizes the plan attachment and provisions balances |
| `invoice.paid` | Records payment, triggers balance provisioning for deferred plans |
| `invoice.created` | Captures usage line items for arrear billing on renewal |
| `customer.subscription.updated` | Syncs subscription status (active, past_due, canceled, etc.) |
| `customer.subscription.deleted` | Expires the plan and activates default plans if configured |

## Direct vs deferred execution

When you call `billing.attach`, MeterPal takes one of two paths depending on whether the customer can be charged immediately:

**Direct (immediate):** The customer already has a payment method. MeterPal creates the Stripe subscription, charges the customer, and provisions balances — all in a single API call.

**Deferred (checkout):** The customer doesn't have a payment method, or the payment requires additional action (like 3DS). MeterPal creates a Stripe Checkout Session (or returns a `required_action`), stores the pending billing plan, and completes everything when the webhook confirms payment.

See [Payment Flow](/documentation/customers/payment-flow) for the full breakdown of redirect modes and checkout behavior.

## What to do in Stripe directly

While MeterPal manages most of the Stripe lifecycle, there are a few things you should handle in Stripe:

| Task | Where |
|---|---|
| Rename products for invoice display | Stripe dashboard |
| View payment logs and disputes | Stripe dashboard |
| Advanced subscription alterations (eg cycle anchors) | Stripe dashboard |
| Everything else (plans, pricing, subscriptions, customers) | **MeterPal** |
